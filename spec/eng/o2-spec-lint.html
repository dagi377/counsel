o2 spec lint: Counsel product spec

Script: eng-spec/o2_lint.py (run python3 -I o2_lint.py [--spec DIR] [--json out] [--fix] [--strict [--baseline FILE]] [--write-baseline]). Scope: 12 area JSON files, access-map*.json, access.json (201 screens, 66 capabilities, 10 roles). build.py after fixes: areas=12 screens=201 missing=[].

Using it as a CI gate

The spec directory is --spec DIR, else $COUNSEL_SPEC_DIR, else ../spec (the Counsel repo layout), else ../legal-spec. Without --strict the script only reports and exits 0. With --strict it exits 1 when any mechanical finding exists, when any judgment check count is above the checked-in baseline o2_lint.baseline.json (missing baseline means every count must be 0), or when the spec directory is missing. The baseline can only shrink: after an owner resolves findings, run --write-baseline and commit the smaller counts. In the Counsel repo, T-001 wires python3 -I tools/o2_lint.py --spec spec --strict into make check. Current baseline: entity-conflict 12, gate-dup 3, gate-no-approver 9; strict run exits 0.
